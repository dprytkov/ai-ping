# claude-ping / codex-ping

[English overview](README.md) | [Краткая инструкция на русском](README.ru.md)

Это два bat-файла. Каждый делает минимальный запрос с входом по подписке: Claude — через Claude Code, Codex — напрямую к серверу ChatGPT с токеном Codex CLI. Запрос проверяет вход и открывает окно лимитов, если оно ещё не активно. При HTTP 401 `codex-ping` использует `codex exec` для обновления авторизации.

| Скрипт | Модель по умолчанию | Расход |
|---|---|---|
| `claude-ping.bat` | `haiku` | короткий системный промпт, без пользовательских инструкций, инструментов и MCP; thinking отключён, effort `low`; фактические токены выводятся после запуска |
| `codex-ping.bat` | `gpt-5.6-luna`, reasoning `low` | минимальный прямой запрос без инструментов; фактические токены выводятся после запуска; при CLI fallback вход больше |

## Установка

Установка из интернета одной командой (нужны `curl.exe` и `tar.exe` в PATH).

**PowerShell 5.1 / 7** — приглашение вида `PS C:\...>`:

```powershell
$aiPingInstaller = Join-Path $env:TEMP 'ai-ping-install.bat'; curl.exe --fail --location --output $aiPingInstaller https://raw.githubusercontent.com/dprytkov/ai-ping/main/install.bat; if ($? -and $LASTEXITCODE -eq 0) { & $aiPingInstaller }
```

**cmd.exe:**

```bat
curl.exe --fail --location --output "%TEMP%\ai-ping-install.bat" https://raw.githubusercontent.com/dprytkov/ai-ping/main/install.bat && call "%TEMP%\ai-ping-install.bat"
```

Не смешивайте синтаксис оболочек: `%TEMP%` и `call` работают в cmd, `$env:TEMP` и `&` — в PowerShell. При ошибке скачивания команда PowerShell не запускает старую копию загрузчика.

Загрузчик [install.bat](install.bat) сохраняет ZIP-архив публичной ветки `main` на диск, распаковывает его через `tar.exe` в отдельную временную папку и вызывает `ai-ping-setup.bat` из этой папки. Архив и папка удаляются после установки. Git и права администратора не нужны; повтор команды обновляет установку. Ошибки сети, пустые или повреждённые архивы и ошибки установщика возвращают код `1`. CLI и вход по подписке нужно настроить отдельно. Сам скачанный загрузчик остаётся в `%TEMP%\ai-ping-install.bat` для проверки.

Загрузчик сохраняет файлы на диск перед вызовом локального установщика. Локальные скрипты используют PowerShell для работы с Windows. Если защита сообщает об обнаружении, проверьте файл и событие; не отключайте антивирус и не добавляйте исключения ради установки.

Установка из уже скачанной папки:

1. Нужны установленные и залогиненные CLI:
   - `claude`: версия с флагами `--safe-mode` и `--effort` (проверено с 2.1.289), вход через `claude`, затем `/login` с подпиской Claude;
   - `codex`: вход через `codex login` с аккаунтом ChatGPT.
2. Запустите установщик из папки проекта:

   ```powershell
   .\ai-ping-setup.bat
   ```

   Держите `ai-ping-setup.bat`, `claude-ping.bat`, `codex-ping.bat` и `LICENSE` в одной папке. Установщик копирует оба ping-скрипта в `%USERPROFILE%\.local\bin`, создаёт папку при необходимости и добавляет её в пользовательский PATH без дубликатов. Текст лицензии копируется туда же как `ai-ping-LICENSE.txt`. Права администратора не нужны. Повторный запуск обновляет установленные скрипты.

   После установки откройте новый терминал. Если PATH ещё не обновился, выйдите из учётной записи Windows и войдите снова. Установщик предупреждает об отсутствующих CLI; их установку и вход нужно выполнить отдельно. Пинги и задачи по расписанию во время установки не запускаются.
3. Проверьте из любого терминала (cmd, PowerShell 5.1 или 7):

   ```
   claude-ping
   codex-ping
   ```

   Оба скрипта выводят `OK`, модель, токены запроса и серверную статистику лимитов: использованную и оставшуюся долю, время сброса и обратный отсчёт для 5-часового и недельного окон.

## Параметры

Единственный аргумент — модель:

```
claude-ping sonnet
codex-ping gpt-5.6-sol
```

Код выхода `0` означает успех, `1` означает ошибку: CLI не найден в PATH, не выполнен вход или модель недоступна.

## Статистика Claude

`claude-ping` читает токены из JSON-результата `claude --output-format json`. Затем получает лимиты авторизованным GET к `https://api.anthropic.com/api/oauth/usage` с заголовком `anthropic-beta: oauth-2025-04-20`. Этот GET не генерирует ответ модели. Пример вывода:

```text
[2026-10-05 10:00:00] OK: 'ok'
  login=claude-user@example.com
  model=haiku
  TOKENS
  input=20  output=3  total=83
  cache_write=10  cached=50

  LIMITS
  5-hour    [##------------------]  remaining=87.5%  used=12.5%
            resets=2026-10-05 12:00:00 +03:00
            in 0d 01:59:59

  weekly    [#######-------------]  remaining=65%  used=35%
            resets=2026-10-10 10:00:00 +03:00
            in 4d 23:59:59
```

- Токены относятся к одному пингу: `input` — вход без кэша, `cache_write` — запись в кэш, `cached` — чтение из кэша, `output` — ответ. `total` складывает эти четыре отдельные категории. Если поле отсутствует, выводится `n/a`; если нет всей статистики — `tokens: unavailable`.
- `used` и `remaining` — проценты лимита аккаунта, а не число токенов за всё окно. API Claude не возвращает точный остаток в токенах.
- `resets` — серверное время сброса в часовом поясе Windows с указанием смещения UTC. `in` — время до сброса в формате «дни, часы:минуты:секунды»; `reset due` — время уже наступило. Отсутствующее или некорректное время отображается как `resets=unknown`, отсутствующие окна — как `limits: unavailable`. Расчёт «сейчас + 5 часов» не используется.
- Авторизация читается после пинга из `%USERPROFILE%\.claude\.credentials.json`, чтобы использовать токен, обновлённый Claude Code. Если задан `CLAUDE_CONFIG_DIR`, используется `.credentials.json` из этой папки. Скрипт самостоятельно не обновляет токены и не переключает аккаунты.

Если пинг прошёл, а статистика лимитов недоступна (включая HTTP 401 или 429), выводится `WARN: limits unavailable`, код выхода остаётся `0`. Ошибка пинга возвращает `1`.

Цвета, шкалы и расположение блоков такие же, как у `codex-ping`: зелёный при использовании лимита ниже 70%, жёлтый от 70%, красный от 90%; `#` — использованная доля, `-` — оставшаяся, `?` — неизвестный процент. Время сброса и обратный отсчёт выведены отдельными строками. Служебный индикатор HTTP-загрузки скрыт.

## Статистика Codex

После пинга `codex-ping` выполняет авторизованный GET к `https://chatgpt.com/backend-api/wham/usage` для получения лимитов. Этот GET не генерирует ответ модели. Вывод имеет следующий вид (числа ниже — пример):

```text
[2026-10-05 10:00:00] OK: 'ok'
  login=codex-user@example.com
  model=gpt-5.6-luna
  TOKENS
  input=20  output=3  total=23
  cached=5  reasoning=1

  LIMITS  plan=plus
  5-hour    [##------------------]  remaining=88%  used=12%
            resets=2026-10-05 12:00:00 +03:00
            in 0d 01:59:59

  weekly    [#######-------------]  remaining=65%  used=35%
            resets=2026-10-10 10:00:00 +03:00
            in 4d 23:59:59
```

- `input` и `output` — входные и выходные токены одного пинга. `cached` входит в `input`, `reasoning` входит в `output`; `total` не прибавляет их повторно. Если сервер или CLI не вернул поле, выводится `n/a`.
- `used` и `remaining` — использованная и оставшаяся доля лимита аккаунта. Сервер возвращает проценты, а не точное число оставшихся токенов.
- `resets` — фактическое время сброса, полученное с сервера, в часовом поясе Windows с указанием смещения UTC. `in` — оставшееся время в формате «дни, часы:минуты:секунды». `reset due` означает, что указанное время уже наступило.
- Окна определяются по длительности, поэтому недельное окно корректно выводится даже тогда, когда сервер прислал его единственным или первым. Если время отсутствует, выводится `resets=unknown`; если нет окон — `limits: unavailable`. Расчёт «сейчас + 5 часов» не используется.
- После HTTP 401 токены пинга читаются из JSON-события `turn.completed` команды `codex exec --json`, а лимиты запрашиваются с обновлённой авторизацией.

В терминале статус успеха зелёный, ошибки красные, предупреждения жёлтые, заголовки голубые. Шкала показывает использованную долю лимита: зелёная до 70%, жёлтая от 70%, красная от 90%. `#` — использованная часть, `-` — оставшаяся; `?` означает, что сервер не вернул процент. Числа рядом со шкалой точные, шкала округлена до 5%. Цвет задаётся средствами PowerShell; при перенаправлении вывода в файл остаётся читаемый текст без управляющих цветовых кодов.

Если пинг прошёл, а получить статистику не удалось, скрипт выводит `WARN: limits unavailable` и сохраняет код успеха `0`.

## Текущий аккаунт

Оба пинга выводят `login=...` — email текущего аккаунта. Claude получает его через `claude auth status --json`, Codex — из поля `email` локального `id_token` в `auth.json`. После 401 fallback Codex перечитывает обновлённую авторизацию. Проверка логина не отправляет запрос к модели; токены, полный JSON авторизации и ошибки проверки логина не выводятся. Если email отсутствует или некорректен, выводится `login=unavailable`; успешный пинг сохраняет код `0`. Перед публикацией логов скройте email.

## Запуск по расписанию

Обычное пятичасовое окно открывается первым запросом и сбрасывается через 5 часов. Если открыть его пингом в 07:00, сброс ожидается в 12:00. Повторный пинг уже активного окна не переносит время сброса; оба скрипта показывают время, которое вернул сервер. Набор и длительность окон зависят от аккаунта.

Создание задач в Планировщике заданий (PowerShell, без прав администратора):

```powershell
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -RunOnlyIfNetworkAvailable `
    -ExecutionTimeLimit (New-TimeSpan -Minutes 5)
$trigger = New-ScheduledTaskTrigger -Daily -At 07:00

foreach ($name in 'claude-ping', 'codex-ping') {
    $action = New-ScheduledTaskAction -Execute 'cmd.exe' `
        -Argument "/c %USERPROFILE%\.local\bin\$name.bat >> %USERPROFILE%\.local\bin\ai-ping.log 2>&1"
    Register-ScheduledTask -TaskName $name -TaskPath '\AI ping\' `
        -Action $action -Trigger $trigger -Settings $settings
}
```

- `-StartWhenAvailable`: если ноутбук спал в 07:00, задача выполнится сразу после пробуждения.
- `-RunOnlyIfNetworkAvailable`: задача не запускается без сети.
- Вывод каждого запуска дописывается в `%USERPROFILE%\.local\bin\ai-ping.log`.
- Задача работает от вашего пользователя и только когда вы вошли в систему, поэтому видит ваш вход в `claude` и `codex`. На время запуска мелькнёт окно cmd.

Несколько запусков в день, например 07:00 и 12:05, чтобы сразу открывать следующее окно:

```powershell
$trigger = @(
    New-ScheduledTaskTrigger -Daily -At 07:00
    New-ScheduledTaskTrigger -Daily -At 12:05
)
```

Подставьте этот `$trigger` в команду регистрации выше.

Управление задачами:

```powershell
Start-ScheduledTask -TaskPath '\AI ping\' -TaskName claude-ping     # запустить сейчас
Get-ScheduledTask -TaskPath '\AI ping\' | Get-ScheduledTaskInfo     # последний запуск и LastTaskResult (0 = OK)
Get-Content $env:USERPROFILE\.local\bin\ai-ping.log -Tail 20        # лог
Unregister-ScheduledTask -TaskPath '\AI ping\' -TaskName claude-ping -Confirm:$false   # удалить
```

## Как экономятся токены

**claude-ping**

| Флаг | Что даёт |
|---|---|
| `--model haiku` | самая дешёвая модель |
| `--system-prompt "..."` | заменяет большой стандартный системный промпт (основная экономия) |
| `--tools ""` | отключает все инструменты, их схемы не отправляются |
| `--strict-mcp-config` | не загружает MCP-серверы |
| `--safe-mode` | отключает пользовательские `CLAUDE.md`, skills, плагины, hooks, память и стили ответа; вход по подписке сохраняется |
| `--effort low` | уменьшает рассуждение на моделях с управлением effort |
| `MAX_THINKING_TOKENS=0` | отключает thinking на поддерживающих это моделях; переменная задаётся только дочернему процессу CLI |
| `CLAUDE_CODE_EFFORT_LEVEL=low` | закрепляет низкий effort только для дочернего процесса, даже если в терминале задан другой уровень |
| `--max-turns 1`, `--no-session-persistence` | один ход, сессия не сохраняется |
| `--output-format json` | токены читаются из результата CLI, без дополнительного запроса к модели |
| запуск из `%TEMP%` | CLI работает вне проекта; `--safe-mode` дополнительно исключает глобальные пользовательские инструкции |

`--bare` не используется: он принимает только `ANTHROPIC_API_KEY`, запрос идёт мимо подписки, и окно не открывается.

Флаги [`--safe-mode` и `--effort`](https://code.claude.com/docs/en/cli-reference) и переменная [`MAX_THINKING_TOKENS`](https://code.claude.com/docs/en/model-config#extended-thinking) применяются к одному пингу; файлы настроек и обычные сеансы Claude Code не меняются. На моделях, где thinking нельзя отключить, остаётся effort `low`.

Расход зависит от модели, версии CLI и кэша; фиксированное число токенов не гарантируется. GET статистики не расходует токены модели; отдельный короткий запрос CLI нужен для проверки доступа и открытия окна лимитов.

**codex-ping**

Основной путь — один POST к `/backend-api/codex/responses`: собственный короткий системный промпт, `tools: []`, без MCP и истории. Следующий GET к `/backend-api/wham/usage` читает лимиты. Флаги ниже используются только при HTTP 401, когда скрипт переходит на Codex CLI:

| Флаг | Что даёт |
|---|---|
| `-m gpt-5.6-luna` | самая дешёвая доступная модель |
| `-c model_reasoning_effort=low` | низкое рассуждение независимо от пользовательской настройки |
| `--ignore-user-config` | не читает `config.toml`: без MCP-серверов; вход сохраняется (`auth.json`) |
| `--cd %TEMP%`, `--skip-git-repo-check` | запуск вне проекта, `AGENTS.md` проекта не подхватывается |
| `--sandbox read-only`, `--ephemeral` | модель ничего не меняет, сессия не сохраняется |
| `--json` | токены читаются из события `turn.completed` |

У CLI fallback системный промпт и встроенные инструменты Codex флагами не отключаются, поэтому он расходует больше входных токенов, чем прямой запрос.

## Проверка изменений

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\test-claude-ping.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\test-codex-ping.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\test-install.ps1
```

Проверки используют временные профили внутри проекта, подставные HTTP-ответы и подставные CLI; живые запросы и реальные токены не используются. Для Claude проверяются модели по умолчанию и явно заданные, запуск через bat, пустой аргумент `--tools ""`, режим `--safe-mode`, низкий effort и отключённое thinking независимо от переменных родительского терминала, запуск вне проекта, токены с кэшем, оба окна, обратный отсчёт, обновлённая авторизация, отсутствие данных, HTTP 401/429, ошибки и коды выхода. Для Codex проверяются обе модели, токены, серверные времена сброса, перестановка и отсутствие окон, HTTP 401 fallback, ошибки и коды выхода. Временные файлы удаляются после проверки.

`test-install.ps1` дополнительно проверяет bat-загрузчик с локальными ZIP-архивами: установку в изолированный профиль с подставным реестром, повторное обновление файлов без дубликатов PATH, существующий PATH с кавычками, ошибки скачивания, пустой или повреждённый архив, отсутствие установщика или curl/tar, ошибки установки и очистку временной папки. Реальный реестр и установленные команды не меняются.

## Модели Codex

Доступность моделей зависит от аккаунта ChatGPT, подписки и версии CLI. Выберите модель, доступную при вашем типе входа, и передайте её единственным аргументом `codex-ping`. Если модель по умолчанию `gpt-5.6-luna` недоступна, используйте другое поддерживаемое имя; сам скрипт не гарантирует доступ к модели.

## Почему bat, а не PowerShell

Windows PowerShell 5.1 молча выбрасывает пустые аргументы при прямом вызове внешних программ. Из-за этого `--tools ""` теряется, и `--tools` забирает следующий флаг как своё значение. Поэтому `claude-ping` запускает CLI через `cmd`, который передаёт `""` корректно. JSON и статистику обрабатывает PowerShell; оба скрипта остаются самостоятельными bat-файлами и работают из любого терминала и из Планировщика.
