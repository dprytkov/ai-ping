# ai-ping / claude-ping / codex-ping

[English overview](README.md) | [Краткая инструкция на русском](README.ru.md)

Для Windows есть два bat-файла, для Linux — два shell-скрипта с общим модулем Python 3. Каждый делает минимальный запрос с входом по подписке: Claude — через Claude Code, Codex — напрямую к серверу ChatGPT с токеном Codex CLI. В Linux при отсутствии CLI можно вставить авторизацию из Windows во время установки; Claude тоже отправляет прямой запрос. Запрос проверяет вход и открывает окно лимитов, если оно ещё не активно. При HTTP 401 `codex-ping` использует `codex exec` для обновления авторизации, если CLI установлен; без него нужно повторить перенос токена.

| Скрипт | Модель по умолчанию | Расход |
|---|---|---|
| `claude-ping.bat` | `haiku` | короткий системный промпт, без пользовательских инструкций, инструментов и MCP; thinking отключён, effort `low`; фактические токены выводятся после запуска |
| `codex-ping.bat` | `gpt-5.6-luna`, reasoning `low` | минимальный прямой запрос без инструментов; фактические токены выводятся после запуска; при CLI fallback вход больше |

## Установка Windows

Установка из интернета одной командой (нужны `curl.exe` и `tar.exe` в PATH).

**Windows PowerShell (5.1 / 7):**

```powershell
irm https://raw.githubusercontent.com/dprytkov/ai-ping/main/install.ps1 | iex
```

**Windows CMD:**

```bat
curl -fsSL https://raw.githubusercontent.com/dprytkov/ai-ping/main/install.bat -o install.bat && install.bat && del install.bat
```

Выберите команду для своего терминала. [install.ps1](install.ps1) скачивает `install.bat` в уникальный временный файл, запускает его только после успешной загрузки и удаляет при завершении. Команда CMD сохраняет `install.bat` в текущую папку и удаляет после успешной установки.

Загрузчик [install.bat](install.bat) сохраняет ZIP-архив публичной ветки `main` на диск, распаковывает его через `tar.exe` в отдельную временную папку и вызывает `ai-ping-setup.bat` из этой папки. Архив и папка удаляются после установки. Git и права администратора не нужны; повтор команды обновляет установку. Ошибки сети, пустые или повреждённые архивы и ошибки установщика возвращают код `1`. CLI и вход по подписке нужно настроить отдельно.

Загрузчик сохраняет файлы на диск перед вызовом локального установщика. Локальные скрипты используют PowerShell для работы с Windows. Если защита сообщает об обнаружении, проверьте файл и событие; не отключайте антивирус и не добавляйте исключения ради установки.

Установка из уже скачанной папки:

1. Нужны установленные и залогиненные CLI:
   - `claude`: версия с флагами `--safe-mode` и `--effort` (проверено с 2.1.289), вход через `claude`, затем `/login` с подпиской Claude;
   - `codex`: вход через `codex login` с аккаунтом ChatGPT.
2. Запустите установщик из папки проекта:

   ```powershell
   .\ai-ping-setup.bat
   ```

   Держите `ai-ping-setup.bat`, `ai-ping.bat`, `claude-ping.bat`, `codex-ping.bat` и `LICENSE` в одной папке. Установщик копирует все три ping-скрипта в `%USERPROFILE%\.local\bin`, создаёт папку при необходимости и добавляет её в пользовательский PATH без дубликатов. Текст лицензии копируется туда же как `ai-ping-LICENSE.txt`. Права администратора не нужны. Повторный запуск обновляет установленные скрипты.

   После установки откройте новый терминал. Если PATH ещё не обновился, выйдите из учётной записи Windows и войдите снова. Установщик предупреждает об отсутствующих CLI; их установку и вход нужно выполнить отдельно. Пинги и задачи по расписанию во время установки не запускаются.
3. Проверьте из любого терминала (cmd, PowerShell 5.1 или 7):

   ```
   claude-ping
   codex-ping
   ```

   Оба скрипта выводят `OK`, модель, токены запроса и серверную статистику лимитов: использованную и оставшуюся долю, время сброса и обратный отсчёт для 5-часового и недельного окон.

## Параметры

Команда `ai-ping` без аргументов запускает Codex, затем Claude с моделями по умолчанию в Windows и Linux. При ошибке одного второй всё равно запускается. Код выхода — `0` только при успехе обоих, иначе `1`. Из папки проекта без установки используйте `.\ai-ping.bat` в Windows или `bash ai-ping.sh` в Linux.

Для отдельных команд `claude-ping` и `codex-ping` единственный аргумент — модель:

```
claude-ping sonnet
codex-ping gpt-5.6-sol
```

Код выхода `0` означает успех, `1` означает ошибку: CLI не найден в PATH, не выполнен вход или модель недоступна.

## Linux

Подходит любой дистрибутив Linux, включая WSL, с Bash, Python 3.8+, службой cron и пользовательской командой `crontab`, `flock` (util-linux), coreutils, awk, grep, curl, tar, gzip и tzdata. Недостающие зависимости установите пакетным менеджером своего дистрибутива. Включите его службу cron: она может называться `cron` или `crond`, а управление зависит от используемой системы инициализации. В WSL расписание работает, пока запущены дистрибутив и его служба cron.

CLI необязательны: при отсутствии `claude` или `codex` установщик запросит авторизацию из Windows, после чего пинги выполняются напрямую через HTTP. Если CLI установлен, выполните вход под обычным пользователем: `claude` → `/login` или `codex login`. Linux-скрипты сохраняют минимальные запросы, используют стандартную библиотеку Python и не требуют pip-пакетов либо jq. `claude-ping.sh` и `codex-ping.sh` вызывают общий `ai-ping.py`; держите их вместе с `ai-ping.sh` рядом с этим модулем для запуска без установки.

Из корня клона или распакованного архива:

```bash
bash ai-ping-setup.sh
```

Установщик спрашивает время первого запуска в формате `HH:MM` и провайдера `both`, `claude` либо `codex`. Значения по умолчанию — `06:00` и `both`; расписание — **06:00, 11:01, 16:02, 21:03 по московскому времени Windows** (`Europe/Moscow`, UTC+3). Без интерактивного терминала используются эти значения расписания. Если выбранный CLI отсутствует, понадобится сохранённая авторизация либо интерактивный ввод. Передайте параметры, чтобы обойти вопросы о расписании (запрос необходимой авторизации остаётся):

```bash
bash ai-ping-setup.sh --start 06:00 --provider both
bash ai-ping-setup.sh --start 07:30 --provider claude --claude-model sonnet
bash ai-ping-setup.sh --start 09:00 --provider codex --codex-model gpt-5.6-sol
bash ai-ping-setup.sh --start 06:00 --provider both --timezone Europe/Berlin
```

**Linux / WSL** — интернет-установка без Git:

```bash
curl -fsSL https://raw.githubusercontent.com/dprytkov/ai-ping/main/install.sh | bash
```

`install.sh` скачивает архив `main.tar.gz` во временную папку и вызывает `ai-ping-setup.sh`. Вопросы о расписании и авторизации читаются из терминала даже при запуске через `curl | bash`. Папка и архив удаляются при успехе и при ошибке. Для передачи параметров используйте `| bash -s -- --start 06:00 --provider both`. Установщики запускайте **без sudo**, чтобы использовать авторизацию вашего аккаунта. Для установки системных зависимостей sudo нужен.

В `~/.local/bin` копируются команды `ai-ping`, `claude-ping`, `codex-ping`, модуль `ai-ping.py`, плановый запуск `ai-ping-run` и лицензия `ai-ping-LICENSE.txt`. В `.profile` и `.bashrc` добавляется помеченный блок PATH с защитой от дубликатов. Повторная установка обновляет файлы и заменяет только блок `# BEGIN AI-PING` / `# END AI-PING` в пользовательском crontab; остальные задачи сохраняются. Установка не отправляет запросы к модели и не выполняет вход.

### Авторизация из Windows без CLI в Linux

Запускайте установку в обычном терминале или SSH-сессии, чтобы можно было вставить текст в запрос. Установщик спрашивает авторизацию только для выбранных провайдеров без CLI. Для `both` вопросы идут по очереди: сначала Claude, затем Codex. Он проверяет формат локально; запросов к моделям при установке нет.

На Windows откройте **Пуск**, наберите **PowerShell** и запустите **Windows PowerShell** без прав администратора. Дальше выберите нужный провайдер:

**Claude**

1. Для cron без Claude CLI в Linux выполните в PowerShell `claude setup-token` и подтвердите доступ в браузере.
2. Скопируйте показанный токен. Он действует один год и разрешает запросы к модели. Статистика лимитов аккаунта с ним недоступна; AI Ping пропускает этот запрос и выводит пояснение. [Долгоживущий токен Claude](https://code.claude.com/docs/en/authentication#generate-a-long-lived-token).
3. Вернитесь в терминал Linux с запросом `claude authorization:`, вставьте через **Ctrl+Shift+V** или правую кнопку мыши и нажмите Enter. Текст скрыт, как при вводе пароля; это нормально.

Для вывода лимитов можно перенести JSON обычного входа, но его временный access-токен истекает и без CLI на сервере не продлевается. Для автоматического продления с лимитами установите Claude CLI в Linux и выполните вход там. Перенос временного JSON из Windows:

1. Выполните `claude`, введите `/login`, войдите в свой аккаунт с подпиской и выйдите из Claude Code.
2. Скопируйте файл авторизации одной строкой:

   ```powershell
   $aiPingAuthDir = if ($env:CLAUDE_CONFIG_DIR) { $env:CLAUDE_CONFIG_DIR } else { Join-Path $env:USERPROFILE '.claude' }; Get-Content -Raw -LiteralPath (Join-Path $aiPingAuthDir '.credentials.json') | ConvertFrom-Json | ConvertTo-Json -Depth 20 -Compress | Set-Clipboard
   ```

   Обычное расположение файла — `C:\Users\ВАШЕ_ИМЯ\.claude\.credentials.json` (`%USERPROFILE%\.claude\.credentials.json`). Если задан `CLAUDE_CONFIG_DIR`, используется эта папка. [Официальная инструкция Claude](https://code.claude.com/docs/en/authentication).
3. Вставьте JSON в запрос `claude authorization:` на Linux.

**Codex**

1. Выполните `codex login` в PowerShell и войдите через свой аккаунт ChatGPT.
2. Скопируйте авторизацию командой:

   ```powershell
   $aiPingAuthDir = if ($env:CODEX_HOME) { $env:CODEX_HOME } else { Join-Path $env:USERPROFILE '.codex' }; Get-Content -Raw -LiteralPath (Join-Path $aiPingAuthDir 'auth.json') | ConvertFrom-Json | ConvertTo-Json -Depth 20 -Compress | Set-Clipboard
   ```

   Обычное расположение — `C:\Users\ВАШЕ_ИМЯ\.codex\auth.json` (`%USERPROFILE%\.codex\auth.json`), при заданном `CODEX_HOME` — файл в этой папке. Если авторизация хранится в системном хранилище и файла нет, откройте `.codex\config.toml` в папке пользователя Windows через Блокнот. Добавьте или измените строку `cli_auth_credentials_store = "file"`, сохраните, снова выполните `codex login` и повторите команду копирования. Для нестандартного `CODEX_HOME` редактируйте `config.toml` в нём. [Официальная инструкция Codex по хранению и переносу авторизации](https://learn.chatgpt.com/docs/auth).
3. Вернитесь в запрос `codex authorization:` на Linux, вставьте текст и нажмите Enter. Не копируйте отдельно API-ключ: нужен JSON входа через ChatGPT.

Неправильный формат вызывает повторный запрос без вывода вставленного текста. При повторной установке Enter оставляет существующую авторизацию, новая вставка заменяет только копию AI Ping. Без интерактивного терминала и без авторизации установка завершается ошибкой до изменения скриптов и расписания. Отмена ввода тоже сохраняет прежнее расписание.

Импорт сохраняется отдельно: `~/.local/state/ai-ping/credentials/claude.json` и `codex.json`, права файлов `600`, папки `700`. Сохраняются только access-токен, права Claude (`scopes`), если они указаны, и `account_id`/`id_token` Codex, если присутствуют; refresh-токены и API-ключи отбрасываются. Стандартные файлы CLI не меняются. Без CLI импорт имеет приоритет над стандартным файлом, если сохранён; с установленным CLI используются его обычный профиль и вход. Не публикуйте авторизацию и не передавайте её аргументом команды. После переноса очистите буфер Windows: `Set-Clipboard -Value ''`.

Импортированные токены автоматически не обновляются. При HTTP 401 создайте новую авторизацию на Windows и повторите установку; для долгоживущего токена Claude снова используйте `claude setup-token`. Прямой запрос Claude без CLI использует `haiku`, `sonnet`, `opus` или полное имя модели API, короткий промпт, до 16 выходных токенов, без инструментов и thinking. CLI-режимы вроде `opusplan` и суффикса `[1m]` требуют установленный CLI. Email Claude без CLI выводится как `login=unavailable`. Токен обычной строкой помечается как `user:inference`: AI Ping выводит `LIMITS unavailable (setup-token permits model requests only).` без HTTP-запроса статистики. JSON обычного входа с расширенными или неизвестными правами сохраняет запрос лимитов. Это относится к ручному запуску и cron; недоступность лимитов не меняет успешный код выхода. Codex получает email из `id_token`, если он есть. Доступ конкретного токена к прямому запросу проверяется первым пингом, а не установкой.

Расписание ежедневное, с шагом **5 часов 1 минута** от первого запуска до **23:00 включительно** в выбранном часовом поясе:

| Первый запуск | Все запуски за день |
|---|---|
| `06:00` (по умолчанию) | `06:00`, `11:01`, `16:02`, `21:03` |
| `07:00` | `07:00`, `12:01`, `17:02`, `22:03` |
| `07:30` | `07:30`, `12:31`, `17:32`, `22:33` |
| `08:00` | `08:00`, `13:01`, `18:02` |
| `09:00` | `09:00`, `14:01`, `19:02` |

Позже 23:00 новые запуски не создаются; уже начатый запрос может закончиться позже. По умолчанию время соответствует Windows с поясом «(UTC+03:00) Москва, Санкт-Петербург» (`Russian Standard Time`), которому в Linux соответствует `Europe/Moscow`. Часовой пояс Windows можно посмотреть в PowerShell: `Get-TimeZone`. Если он другой, передайте установщику соответствующее имя IANA через `--timezone`. Проверить часы выбранного пояса на Linux можно командой `TZ=Europe/Moscow date`. Системный пояс Linux менять не требуется.

В crontab будет одна строка `* * * * * ... --scheduled` и комментарий с часами расписания. Она проверяет время каждую минуту; сам `ai-ping-run` отправляет запросы только в указанные минуты в выбранном поясе. Это работает и на сервере в UTC: например, 06:00 московского времени соответствует 03:00 UTC. Проверка выбранного пояса внутри запуска позволяет соблюдать расписание независимо от системного пояса и особенностей cron в дистрибутиве. Другие cron-задачи сохраняют прежнее время. Без аргумента `--scheduled` команда `ai-ping-run` запускает пинги сразу, как и раньше.

Для поясов с летним временем учитываются правила `tzdata`; интервал задан по часам этого пояса, поэтому фактическое прошедшее время в день перевода часов может отличаться. Пропущенные при выключении или сне пинги не догоняются. На следующий день расписание снова начинается с заданного утреннего времени. Ошибка пинга не отменяет последующие запуски. После смены пояса в Windows повторите установку с нужным `--timezone`.

Плановый запуск не требует активной SSH-сессии. Нужны работающий компьютер, интернет и активный сервис cron. Скрипт сохраняет PATH на момент установки, `CLAUDE_CONFIG_DIR` и `CODEX_HOME`, если они заданы, чтобы видеть CLI и выбранный профиль без загрузки интерактивных настроек оболочки. Codex читает `CODEX_HOME/auth.json` (по умолчанию `~/.codex/auth.json`); для прямого запроса нужен ChatGPT-токен в файле. Claude после CLI-пинга читает `CLAUDE_CONFIG_DIR/.credentials.json` (по умолчанию `~/.claude/.credentials.json`). При отсутствии CLI используется импорт AI Ping, если сохранён. При обновлении CLI или перемещении его в другой PATH повторите установку.

Через `flock` блокируются одновременные плановые запуски. Для `both` оба провайдера запускаются последовательно; ошибка первого не мешает второму. Общий код выхода — `1`, если хотя бы один пинг не удался. Вывод дописывается в `~/.local/state/ai-ping/ai-ping.log`; он может содержать email аккаунта, скройте его перед публикацией. Старые записи можно удалить вручную.

После установки откройте новый терминал Bash либо выполните `export PATH="$HOME/.local/bin:$PATH"`. Проверка и управление:

```bash
claude-ping
codex-ping
crontab -l
tail -n 40 ~/.local/state/ai-ping/ai-ping.log
~/.local/bin/ai-ping-run  # реальный запуск обоих выбранных пингов сейчас
crontab -e              # удалить только блок BEGIN AI-PING / END AI-PING для отмены расписания
```

Состояние службы `cron` или `crond` проверьте средствами своего дистрибутива.

Для изменения времени или моделей снова запустите установщик с нужными параметрами. Это не создаёт дубликаты задач или блоков PATH. В Linux JSON передаётся напрямую через Python, поэтому пустой аргумент `--tools ""` не теряется. Вывод Linux содержит обычный текст без цветовых управляющих кодов; reset-time выводится с локальным смещением UTC.

## Веб-панель

Исходники дополнительной панели находятся в [web](web/README.md). Она запускает существующие Linux-команды, показывает общий журнал, позволяет выбрать аккаунт и модель, импортировать авторизацию из Windows и управлять расписанием. Вход через HTML-форму с паролем, сессия действует 8 часов. Поддерживаются до 12 аккаунтов; два встроенных серверных нельзя удалять, но можно обновлять и исключать из расписания.

Для установки нужен Ubuntu/Debian-сервер с AI Ping для root в `/root/.local/bin`, импортированной авторизацией обоих провайдеров, cron, systemd, sudo и существующим HTTPS vhost Nginx. Обычные установщики Windows/Linux панель не устанавливают. На целевом Linux-сервере:

```sh
cd /path/to/ai-ping/web
python3 -m unittest -v test_web.py test_profiles.py test_deploy.py
sudo python3 deploy.py --host panel.example.com --vhost /etc/nginx/sites-enabled/panel.conf
```

Домен и абсолютный путь в примере замените своими. Панель будет доступна по `https://<ваш-домен>/ai-ping/`. Развёртывание сохраняет резервные копии, проверяет конфигурации и HTTPS-вход, при ошибке восстанавливает файлы. Оно не делает пинги к моделям. Подробные требования и порядок отключения/отката — в [web/README.md](web/README.md).

Во вкладке **Аккаунты** импортируйте `%USERPROFILE%\.claude\.credentials.json` или `%USERPROFILE%\.codex\auth.json`; для Claude также подходит `claude setup-token`. Можно скачать из панели скрипт и выполнить в Windows:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Import-WindowsAccounts.ps1 -PanelUrl 'https://panel.example.com/ai-ping/' -AccountName 'Мой Windows'
```

Укажите свой адрес панели. Скрипт запросит её логин/пароль и добавит оба профиля из стандартных Windows-папок. При нестандартных `CLAUDE_CONFIG_DIR`/`CODEX_HOME` используйте импорт файла через панель. Повторный запуск добавляет новые профили; обновляйте существующие кнопкой **Обновить авторизацию**. API-ключи и refresh-токены не сохраняются; импортированные access-токены не обновляются автоматически.

Во вкладке **Расписание** задайте часы, часовой пояс, модели и участвующие аккаунты; автоматический запуск можно приостановить. Начальные значения: **06:00, 11:01, 16:02, 21:03 Europe/Moscow**, модели `haiku` и `gpt-5.6-luna`, оба встроенных аккаунта. Новые аккаунты включаются только вручную. После установки панели расписание берётся из её настроек, а не из старого комментария crontab. Строка cron сохраняется; wrapper использует общую блокировку `run.lock` и не выполняет один слот дважды. При другом прежнем расписании установите нужные значения через панель. Обновление основной Linux-установки перезаписывает wrapper — после него повторите развёртывание панели.

Ручной запуск расходует лимиты подписки; чтение панели и журнала не делает запросов к моделям. Последние 64 КБ журнала берутся из `/root/.local/state/ai-ping/ai-ping.log`; последний ручной результат сбрасывается при перезапуске службы. Секреты хранятся вне исходников, файлы авторизации имеют права `600`, каталог состояния панели — `700`.

## Статистика Claude

`claude-ping` читает токены из JSON-результата `claude --output-format json`; без CLI в Linux — из `usage` прямого ответа Messages API. Затем получает лимиты авторизованным GET к `https://api.anthropic.com/api/oauth/usage` с заголовком `anthropic-beta: oauth-2025-04-20`. Этот GET не генерирует ответ модели. Пример вывода:

```text
[2026-10-05 10:00:00] OK: 'ok'
  login=claude-user@example.com
  model=haiku
  TOKENS
  input=20  output=3  total=83
  cache_write=10  cached=50

  LIMITS
  5-hour    [##------------------]  remaining=87.5%  used=12.5%
            resets=2026-10-05 12:00:00 +03:00
            in 0d 01:59:59

  weekly    [#######-------------]  remaining=65%  used=35%
            resets=2026-10-10 10:00:00 +03:00
            in 4d 23:59:59
```

- Токены относятся к одному пингу: `input` — вход без кэша, `cache_write` — запись в кэш, `cached` — чтение из кэша, `output` — ответ. `total` складывает эти четыре отдельные категории. Если поле отсутствует, выводится `n/a`; если нет всей статистики — `tokens: unavailable`.
- `used` и `remaining` — проценты лимита аккаунта, а не число токенов за всё окно. API Claude не возвращает точный остаток в токенах.
- `resets` — серверное время сброса в часовом поясе компьютера с указанием смещения UTC. `in` — время до сброса в формате «дни, часы:минуты:секунды»; `reset due` — время уже наступило. Отсутствующее или некорректное время отображается как `resets=unknown`, отсутствующие окна — как `limits: unavailable`. Расчёт «сейчас + 5 часов» не используется.
- Авторизация читается после пинга из `%USERPROFILE%\.claude\.credentials.json`, чтобы использовать токен, обновлённый Claude Code. Если задан `CLAUDE_CONFIG_DIR`, используется `.credentials.json` из этой папки. Скрипт самостоятельно не обновляет токены и не переключает аккаунты.

Если пинг прошёл, а статистика лимитов недоступна (включая HTTP 401 или 429), выводится `WARN: limits unavailable`, код выхода остаётся `0`. Ошибка пинга возвращает `1`.

В Windows статистика лимитов запрашивается и после неудачного пинга. Если Claude сообщает об исчерпании лимита, вместо ошибки выводится обычное сообщение `LIMIT: quota exhausted. Try again after reset.`, затем блок `LIMITS` с остатком и серверным временем сброса. Другие ошибки сохраняют `FAIL`. Если получить статистику не удалось, выводится `WARN: limits unavailable`; код неуспешного пинга остаётся `1`. При отсутствии CLI или некорректном имени модели запрос статистики не выполняется.

В Windows цвета, шкалы и расположение блоков такие же, как у `codex-ping`: зелёный при использовании лимита ниже 70%, жёлтый от 70%, красный от 90%; `#` — использованная доля, `-` — оставшаяся, `?` — неизвестный процент. Время сброса и обратный отсчёт выведены отдельными строками. Служебный индикатор HTTP-загрузки скрыт. Linux выводит те же шкалы обычным текстом.

## Статистика Codex

После пинга `codex-ping` выполняет авторизованный GET к `https://chatgpt.com/backend-api/wham/usage` для получения лимитов. Этот GET не генерирует ответ модели. Вывод имеет следующий вид (числа ниже — пример):

```text
[2026-10-05 10:00:00] OK: 'ok'
  login=codex-user@example.com
  model=gpt-5.6-luna
  TOKENS
  input=20  output=3  total=23
  cached=5  reasoning=1

  LIMITS  plan=plus
  5-hour    [##------------------]  remaining=88%  used=12%
            resets=2026-10-05 12:00:00 +03:00
            in 0d 01:59:59

  weekly    [#######-------------]  remaining=65%  used=35%
            resets=2026-10-10 10:00:00 +03:00
            in 4d 23:59:59
```

- `input` и `output` — входные и выходные токены одного пинга. `cached` входит в `input`, `reasoning` входит в `output`; `total` не прибавляет их повторно. Если сервер или CLI не вернул поле, выводится `n/a`.
- `used` и `remaining` — использованная и оставшаяся доля лимита аккаунта. Сервер возвращает проценты, а не точное число оставшихся токенов.
- `resets` — фактическое время сброса, полученное с сервера, в часовом поясе компьютера с указанием смещения UTC. `in` — оставшееся время в формате «дни, часы:минуты:секунды». `reset due` означает, что указанное время уже наступило.
- Окна определяются по длительности, поэтому недельное окно корректно выводится даже тогда, когда сервер прислал его единственным или первым. Если время отсутствует, выводится `resets=unknown`; если нет окон — `limits: unavailable`. Расчёт «сейчас + 5 часов» не используется.
- После HTTP 401 токены пинга читаются из JSON-события `turn.completed` команды `codex exec --json`, а лимиты запрашиваются с обновлённой авторизацией.

В Windows-терминале статус успеха зелёный, ошибки красные, предупреждения жёлтые, заголовки голубые. Шкала показывает использованную долю лимита: зелёная до 70%, жёлтая от 70%, красная от 90%. `#` — использованная часть, `-` — оставшаяся; `?` означает, что сервер не вернул процент. Числа рядом со шкалой точные, шкала округлена до 5%. Цвет задаётся средствами PowerShell; при перенаправлении вывода в файл остаётся читаемый текст без управляющих цветовых кодов. Linux всегда выводит обычный текст.

Если пинг прошёл, а получить статистику не удалось, скрипт выводит `WARN: limits unavailable` и сохраняет код успеха `0`.

В Windows `codex-ping` запрашивает статистику и после HTTP-ошибки, ошибки потока или неудачного CLI-перехода. При сообщении провайдера об исчерпании лимита выводится `LIMIT: quota exhausted. Try again after reset.`, затем остаток и время сброса; `FAIL` не выводится. Обычные ошибки сети, авторизации и временный HTTP 429 без признака исчерпанной квоты сохраняют `FAIL`. Недоступность статистики даёт предупреждение; код неуспешного пинга остаётся `1`. При отсутствии или некорректной авторизации до запроса пинга статистика не запрашивается.

## Текущий аккаунт

Оба пинга выводят `login=...` — email текущего аккаунта. Claude получает его через `claude auth status --json`, Codex — из поля `email` локального `id_token` в авторизации. Без CLI Claude выводит `login=unavailable`. После 401 fallback Codex перечитывает обновлённую авторизацию. Проверка логина не отправляет запрос к модели; токены, полный JSON авторизации и ошибки проверки логина не выводятся. Если email отсутствует или некорректен, выводится `login=unavailable`; успешный пинг сохраняет код `0`. Перед публикацией логов скройте email.

## Запуск по расписанию

Обычное пятичасовое окно открывается первым запросом и сбрасывается через 5 часов. Если открыть его пингом в 07:00, сброс ожидается в 12:00. Повторный пинг уже активного окна не переносит время сброса; оба скрипта показывают время, которое вернул сервер. Набор и длительность окон зависят от аккаунта.

Создание задач в Планировщике заданий (PowerShell, без прав администратора):

```powershell
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -RunOnlyIfNetworkAvailable `
    -ExecutionTimeLimit (New-TimeSpan -Minutes 5)
$trigger = New-ScheduledTaskTrigger -Daily -At 07:00

foreach ($name in 'claude-ping', 'codex-ping') {
    $action = New-ScheduledTaskAction -Execute 'cmd.exe' `
        -Argument "/c %USERPROFILE%\.local\bin\$name.bat >> %USERPROFILE%\.local\bin\ai-ping.log 2>&1"
    Register-ScheduledTask -TaskName $name -TaskPath '\AI ping\' `
        -Action $action -Trigger $trigger -Settings $settings
}
```

- `-StartWhenAvailable`: если ноутбук спал в 07:00, задача выполнится сразу после пробуждения.
- `-RunOnlyIfNetworkAvailable`: задача не запускается без сети.
- Вывод каждого запуска дописывается в `%USERPROFILE%\.local\bin\ai-ping.log`.
- Задача работает от вашего пользователя и только когда вы вошли в систему, поэтому видит ваш вход в `claude` и `codex`. На время запуска мелькнёт окно cmd.

Несколько запусков в день, например 07:00 и 12:05, чтобы сразу открывать следующее окно:

```powershell
$trigger = @(
    New-ScheduledTaskTrigger -Daily -At 07:00
    New-ScheduledTaskTrigger -Daily -At 12:05
)
```

Подставьте этот `$trigger` в команду регистрации выше.

Управление задачами:

```powershell
Start-ScheduledTask -TaskPath '\AI ping\' -TaskName claude-ping     # запустить сейчас
Get-ScheduledTask -TaskPath '\AI ping\' | Get-ScheduledTaskInfo     # последний запуск и LastTaskResult (0 = OK)
Get-Content $env:USERPROFILE\.local\bin\ai-ping.log -Tail 20        # лог
Unregister-ScheduledTask -TaskPath '\AI ping\' -TaskName claude-ping -Confirm:$false   # удалить
```

## Как экономятся токены

**claude-ping**

| Флаг | Что даёт |
|---|---|
| `--model haiku` | самая дешёвая модель |
| `--system-prompt "..."` | заменяет большой стандартный системный промпт (основная экономия) |
| `--tools ""` | отключает все инструменты, их схемы не отправляются |
| `--strict-mcp-config` | не загружает MCP-серверы |
| `--safe-mode` | отключает пользовательские `CLAUDE.md`, skills, плагины, hooks, память и стили ответа; вход по подписке сохраняется |
| `--effort low` | уменьшает рассуждение на моделях с управлением effort |
| `MAX_THINKING_TOKENS=0` | отключает thinking на поддерживающих это моделях; переменная задаётся только дочернему процессу CLI |
| `CLAUDE_CODE_EFFORT_LEVEL=low` | закрепляет низкий effort только для дочернего процесса, даже если в терминале задан другой уровень |
| `--max-turns 1`, `--no-session-persistence` | один ход, сессия не сохраняется |
| `--output-format json` | токены читаются из результата CLI, без дополнительного запроса к модели |
| запуск из `%TEMP%` | CLI работает вне проекта; `--safe-mode` дополнительно исключает глобальные пользовательские инструкции |

`--bare` не используется: он принимает только `ANTHROPIC_API_KEY`, запрос идёт мимо подписки, и окно не открывается.

Флаги [`--safe-mode` и `--effort`](https://code.claude.com/docs/en/cli-reference) и переменная [`MAX_THINKING_TOKENS`](https://code.claude.com/docs/en/model-config#extended-thinking) применяются к одному пингу; файлы настроек и обычные сеансы Claude Code не меняются. На моделях, где thinking нельзя отключить, остаётся effort `low`.

Расход зависит от модели, версии CLI и кэша; фиксированное число токенов не гарантируется. GET статистики не расходует токены модели; отдельный короткий запрос CLI нужен для проверки доступа и открытия окна лимитов.

**codex-ping**

Основной путь — один POST к `/backend-api/codex/responses`: собственный короткий системный промпт, `tools: []`, без MCP и истории. Следующий GET к `/backend-api/wham/usage` читает лимиты. Флаги ниже используются только при HTTP 401, когда скрипт переходит на Codex CLI:

| Флаг | Что даёт |
|---|---|
| `-m gpt-5.6-luna` | самая дешёвая доступная модель |
| `-c model_reasoning_effort=low` | низкое рассуждение независимо от пользовательской настройки |
| [`--ignore-user-config`](https://learn.chatgpt.com/docs/developer-commands?surface=cli) | не читает `config.toml`: без MCP-серверов; вход сохраняется (`auth.json`) |
| `--cd %TEMP%`, `--skip-git-repo-check` | запуск вне проекта, `AGENTS.md` проекта не подхватывается |
| `--sandbox read-only`, `--ephemeral` | модель ничего не меняет, сессия не сохраняется |
| `--json` | токены читаются из события `turn.completed` |

У CLI fallback системный промпт и встроенные инструменты Codex флагами не отключаются, поэтому он расходует больше входных токенов, чем прямой запрос.

## Проверка изменений

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\test-claude-ping.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\test-codex-ping.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\test-install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\test-ai-ping.ps1
```

Проверки используют временные профили внутри проекта, подставные HTTP-ответы и подставные CLI; живые запросы и реальные токены не используются. Для Claude проверяются модели по умолчанию и явно заданные, запуск через bat, пустой аргумент `--tools ""`, режим `--safe-mode`, низкий effort и отключённое thinking независимо от переменных родительского терминала, запуск вне проекта, токены с кэшем, оба окна, обратный отсчёт, обновлённая авторизация, отсутствие данных, HTTP 401/429, ошибки и коды выхода. Для Codex проверяются обе модели, токены, серверные времена сброса, перестановка и отсутствие окон, HTTP 401 fallback, ошибки и коды выхода. Временные файлы удаляются после проверки.

`test-install.ps1` дополнительно проверяет bat-загрузчик с локальными ZIP-архивами: установку в изолированный профиль с подставным реестром, повторное обновление файлов без дубликатов PATH, существующий PATH с кавычками, ошибки скачивания, пустой или повреждённый архив, отсутствие установщика или curl/tar, ошибки установки и очистку временной папки. Реальный реестр и установленные команды не меняются.

Linux-проверки:

```bash
python3 test-linux.py
bash test-linux.sh
```

Python-проверки подставляют ответы HTTP и CLI, проверяют модели, токены, время сброса, отсутствующую авторизацию, ошибки и HTTP 401 fallback. Также проверяются импорт из Windows, скрытый ввод, повторный запрос неверного формата, отмена, отсутствие секретов в выводе, отдельное хранение без refresh-токенов, прямые пинги без CLI и инструкция при истечении токена. Права `600`/`700` проверяются на файловой системе Linux с поддержкой chmod. Shell-проверки используют отдельный HOME, подставной crontab и локальные архивы: проверяют расписание и границу 23:00, обновление без дубликатов, сохранение чужих задач и расписания при ошибке авторизации, пути с пробелами, ошибки загрузки и установки, а также очистку временных файлов. Реальные аккаунты, cron-задачи и сеть не используются.

Офлайн-проверки панели выполняются на Linux, без настоящих аккаунтов и обращений к моделям:

```sh
cd web
python3 -m unittest -v test_web.py test_profiles.py test_deploy.py
sh -n ai-ping-run.sh
```

## Модели Codex

Доступность моделей зависит от аккаунта ChatGPT, подписки и версии CLI. Выберите модель, доступную при вашем типе входа, и передайте её единственным аргументом `codex-ping`. Если модель по умолчанию `gpt-5.6-luna` недоступна, используйте другое поддерживаемое имя; сам скрипт не гарантирует доступ к модели.

## Почему bat, а не PowerShell

Windows PowerShell 5.1 молча выбрасывает пустые аргументы при прямом вызове внешних программ. Из-за этого `--tools ""` теряется, и `--tools` забирает следующий флаг как своё значение. Поэтому `claude-ping` запускает CLI через `cmd`, который передаёт `""` корректно. JSON и статистику обрабатывает PowerShell; оба скрипта остаются самостоятельными bat-файлами и работают из любого терминала и из Планировщика.
