# Серверная авторизация Codex

Для установки достаточно [обычного Linux-установщика](README.ru.md#linux) и подтверждения входа по ссылке и одноразовому коду. После нового входа установщик отправляет один проверочный пинг. При повторной установке действующая сессия сохраняется. Windows-скрипты не меняются.

## Как это работает

- Официальный Codex CLI `0.163.0` устанавливается для Linux x86_64 в `~/.local/lib/ai-ping/codex`. Загрузка проверяется по закреплённой SHA-256. Он не добавляется в PATH и не заменяет личный CLI.
- Единственная активная серверная авторизация находится в `~/.local/state/ai-ping/codex/auth.json`, файл `600`, каталог `700`. OAuth-вход и ротацией refresh-токена управляет официальный CLI.
- Перед пингом `codex_auth.py` проверяет срок токена. При остатке меньше часа, включая истёкший токен, вызывает `account/read` с `refreshToken: true` через Codex App Server. Свежий токен не требует запуска CLI. При HTTP 401 выполняется одно принудительное обновление и одна повторная попытка запроса.
- Блокировка авторизации предотвращает одновременное обновление. Отдельного таймера, постоянно работающего процесса, копирования токенов и зависимости от панели нет. Обновление не запускает модель и инструменты.
- Панель читает тот же файл для `server-codex`. Старые импортированные аккаунты продолжают использовать собственные файлы и не обновляются автоматически. Явный `CODEX_HOME` сохраняет прежний выбор CLI-профиля; при установке отдельной сессии его нужно убрать.

[Авторизация Codex](https://learn.chatgpt.com/docs/auth) · [App Server](https://learn.chatgpt.com/docs/app-server).

## Повторный вход

Если OpenAI отозвал сессию:

```sh
python3 ~/.local/bin/ai-ping.py --codex-login
```

Подтвердите **новый код из терминала** в браузере. Команда завершится проверочным пингом. Обычное истечение access-токена повторного входа не требует. Ошибки обновления останавливают пинг; повторная ручная или плановая попытка повторит проверку.

Для проверки:

```sh
~/.local/bin/codex-ping
tail -n 40 ~/.local/state/ai-ping/ai-ping.log
```

Не публикуйте `auth.json`: он содержит access- и refresh-токены. Резервные копии этой папки должны иметь такой же ограниченный доступ. Не используйте одну ротируемую сессию одновременно на Windows и сервере.

## Переход с прежнего помощника в /opt/ai-ping-codex

Для существующей установки сначала сохраните закрытую резервную копию скриптов, профиля и расписания. Остановите старый таймер, если он ещё установлен:

```sh
systemctl disable --now ai-ping-codex-refresh.timer
systemctl stop ai-ping-codex-refresh.service
```

Обычная установка предложит новый серверный вход. Чтобы сохранить уже подтверждённую отдельную серверную сессию без повторного входа, при остановленных пингах перенесите `/opt/ai-ping-codex/home/auth.json` в `~/.local/state/ai-ping/codex/auth.json` (каталог `700`, файл `600`), а бинарник — в `~/.local/lib/ai-ping/codex` (`755`). Не перезаписывайте существующую новую сессию. После переноса старый помощник не должен обращаться к прежнему профилю.

Обновите установленные `ai-ping.py`, `codex_auth.py`, `codex-ping` и модули панели `store.py`/`runner.py` из одной версии репозитория. Старый вызов `/opt/ai-ping-codex/refresh.py --ping` в `codex-ping` больше не нужен. При обновлении через основной установщик повторно разверните панель, чтобы восстановить её cron-wrapper. Проверьте пинг из панели и обычной команды; в панели должен отображаться новый срок авторизации. Старые credentials и резервные копии можно хранить для отката, но они не являются активным источником.

Откат: остановите пинги, верните совместимые прежние скрипты и перенесите **текущую** авторизацию обратно в старый профиль. Старый сохранённый refresh-токен после ротации может уже не работать; не восстанавливайте его поверх текущего. Верните прежний wrapper расписания и проверьте пинг перед возобновлением запусков.
