# Веб-панель AI Ping

Дополнительная панель для Linux-сервера с существующей установкой AI Ping, cron и HTTPS в Nginx. Исходники находятся в каталоге `web` этого репозитория. Обычные установщики Windows/Linux панель не разворачивают.

Панель запускает установленные `claude-ping` и `codex-ping`, показывает результаты и последние 64 КБ общего журнала. Во вкладке **Запуск** выбираются сервис, модель и аккаунт. Каждый запуск делает настоящий запрос и расходует лимиты подписки; открытие панели и чтение журнала не отправляют запросы к моделям.

## Аккаунты и авторизация из Windows

Во вкладке **Аккаунты** можно добавить профиль, обновить авторизацию и удалить импортированный профиль. Поддерживаются до 12 аккаунтов, включая два встроенных серверных. Встроенные аккаунты можно обновлять и исключать из расписания, но нельзя удалять.

Для импорта выберите сервис, имя и JSON-файл из Windows:

- Claude: `%USERPROFILE%\.claude\.credentials.json`.
- Codex: `%USERPROFILE%\.codex\auth.json`.

Для Claude также можно вставить токен `claude setup-token`. Он разрешает пинги, но при scope `user:inference` статистика лимитов недоступна. Импортированный JSON обычного входа может предоставлять лимиты. API-ключи и refresh-токены не сохраняются. Токены не выводятся в интерфейс; при истечении доступа используйте **Обновить авторизацию** и свежий файл. Автоматического обновления импортированных токенов нет.

Скрипт можно скачать из панели или взять из этого каталога. Укажите адрес своей панели:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Import-WindowsAccounts.ps1 -PanelUrl 'https://panel.example.com/ai-ping/' -AccountName 'Мой Windows'
```

`panel.example.com` — пример, замените его своим доменом. Скрипт запросит логин и пароль панели, прочитает стандартные файлы текущего Windows-профиля и добавит оба аккаунта. При нестандартных `CLAUDE_CONFIG_DIR`/`CODEX_HOME` импортируйте файл через панель. Каждый запуск скрипта добавляет новые профили; существующие обновляйте через панель.

## Расписание и журнал

Начальные настройки: **06:00, 11:01, 16:02, 21:03 Europe/Moscow**, модели `haiku` и `gpt-5.6-luna`, оба встроенных аккаунта. Во вкладке **Расписание** можно изменить часы, часовой пояс, модели и участников, а также приостановить запуск. Новые аккаунты не включаются автоматически. Настройки действуют со следующего запуска без перезапуска службы.

Cron и ручной запуск используют одну блокировку `run.lock`. Один календарный слот выполняется не более одного раза; пропущенные слоты не догоняются. Панель заменяет cron-wrapper, сохраняя строку запуска каждую минуту в crontab. После установки панели актуальное расписание хранится в `web/settings.json`, а прежний комментарий crontab больше его не определяет. Первое развёртывание использует начальные настройки выше; при другом прежнем расписании задайте нужные значения через панель.

Общий журнал: `/root/.local/state/ai-ping/ai-ping.log`. Последний ручной результат хранится в памяти веб-службы до перезапуска. Журнал может содержать email; скрывайте его перед публикацией.

## Требования и развёртывание

Текущий вариант рассчитан на Ubuntu/Debian с Python 3.9+, `tzdata`, Bash, cron, sudo, systemd и Nginx. AI Ping должен быть установлен для root в `/root/.local/bin`, с сохранённой импортированной авторизацией обоих провайдеров в `/root/.local/state/ai-ping/credentials/` и существующим cron-вызовом `ai-ping-run`. Панель использует эти профили, а не произвольные CLI-профили. Для импортированных аккаунтов нужен режим без установленных провайдерских CLI на сервере: он читает авторизацию из изолированного `HOME`.

Нужен существующий HTTPS vhost с сертификатом и единственной строкой `server_name` для выбранного домена. Порт backend `127.0.0.1:18082` должен быть свободен. Развёртывание добавляет маршрут `/ai-ping/` в указанный файл, создаёт пользователя `ai-ping-web`, sudoers и systemd-службу, заменяет root cron-wrapper и перезагружает Nginx. Запускайте эту команду только на целевом Linux-сервере:

```sh
cd /path/to/ai-ping/web
python3 -m unittest -v test_web.py test_profiles.py test_deploy.py
sudo python3 deploy.py --host panel.example.com --vhost /etc/nginx/sites-enabled/panel.conf
```

Замените домен и абсолютный путь своим HTTPS vhost. Файл должен содержать один соответствующий `server_name panel.example.com;`; несколько имён в одной директиве не поддерживаются. URL панели будет `https://<ваш-домен>/ai-ping/`. `--help` показывает параметры без изменений сервера.

`deploy.py` проверяет офлайн-тесты, shell, sudoers, unit и `nginx -t`. Перед записью сохраняет файлы в `/var/backups/ai-ping-web/<UTC timestamp>/`; при ошибке восстанавливает файлы и состояние веб-службы. Пароль, профили и настройки сохраняются при повторном развёртывании. Crontab проверяется на неизменность. Команда выводит сгенерированные реквизиты входа; храните их приватно. Развёртывание проверяет HTTPS и вход, но не отправляет пинги к моделям.

Проверка настоящего запуска через HTTPS выполняется отдельно и расходует по одному пингу Claude/Codex:

```sh
sudo python3 verify_live.py
```

Обычный Linux-установщик перезаписывает `ai-ping-run`. После обновления основных скриптов повторно выполните развёртывание панели, чтобы восстановить её wrapper и управление расписанием.

## Устройство и хранение

- `server.py` — Python stdlib, loopback-порт `18082`, непривилегированный пользователь `ai-ping-web`.
- `runner.py` — root helper через sudo: только статус, запуск существующих команд, расписание и управление аккаунтами. Аргументы проверяются, `shell=True` не используется. Авторизация передаётся JSON через stdin.
- `store.py` — настройки, проверка аккаунтов и приватное хранение; импорт использует `authorization_data` из существующего `ai-ping.py`.
- `ai-ping-web.service` — systemd, лимит памяти 96 МБ и CPU 20%; sudo требует разрешённых повышений привилегий.
- `/opt/ai-ping-web` — установленный код; `/etc/ai-ping-web/access.json` — реквизиты входа (`600`); `service.env` — настройки backend.
- `/root/.local/state/ai-ping/web` — настройки и метаданные (`700`); `accounts/<id>` — изолированные профили; JSON авторизации имеет права `600`. Обновлённые и удалённые credentials архивируются в `web/backups`.

Вход через HTML-форму; пароль проверяется по PBKDF2-SHA256. Случайная сессия действует 8 часов, cookie имеет `Secure; HttpOnly; SameSite=Strict` и область `/ai-ping/`. Выход и перезапуск службы завершают сессии. POST требует JSON, правильный Origin и специальный заголовок. Nginx ограничивает частоту запросов; секрет proxy предотвращает прямой доступ к backend. `/health` через proxy возвращает только `ready: true`.

При перегенерации Nginx vhost сохраняйте `include /etc/nginx/snippets/ai-ping-web.conf;`. Для отключения панели удалите include, проверьте `nginx -t`, перезагрузите Nginx и выполните `systemctl disable --now ai-ping-web`. Cron продолжит работу через helper. Для полного возврата прежнего cron-wrapper восстановите его из резервной копии развёртывания; список соответствий файлов находится в `manifest.json`.

## Офлайн-проверки

На Linux запускайте тесты из каталога `web`. Они используют временные профили, подставные subprocess/HTTP-ответы и фиктивные токены. Настоящие аккаунты, cron и серверные службы не меняются.

```sh
python3 -m unittest -v test_web.py test_profiles.py test_deploy.py
sh -n ai-ping-run.sh
```

Проверяются вход и сессии, CSRF, некорректные команды и модели, защита журнала, повторный запуск, общая блокировка cron/web, импорт/обновление/архивация аккаунтов, расписание, права файлов, удаление refresh-токенов настоящим модулем AI Ping и параметры развёртывания.
